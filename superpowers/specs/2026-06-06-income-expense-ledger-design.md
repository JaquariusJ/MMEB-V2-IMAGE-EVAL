# 收支流水与收入统计设计

## 背景

当前系统的“我的支出”模块只表达支出：支出分类、支出计划、支出流水、支出分析。用户现在需要加入收入记录，并按月统计收入。收入和支出应使用统一流水模型，在 web 端和 iOS/mobile 端保持一致体验。

本设计采用“统一收支流水”方案：在现有支出流水和分类模型上增加类型字段，用 `EXPENSE` 表示支出，用 `INCOME` 表示收入。现有历史流水默认迁移为支出。

## 目标

- 将“我的支出”升级为“我的收支”。
- 在同一个流水功能中录入、筛选、展示收入和支出。
- 每个月统计收入、支出、结余，其中结余 = 收入 - 支出。
- 收入分类和支出分类相互独立。
- 预算计划保留为支出预算，不纳入收入计划。
- web 端和 iOS/mobile 端都完成对应功能与文案更新。

## 非目标

- 不新增收入预算或收入计划。
- 不把现有数据库表大规模重命名为 `transactions`。
- 不在第一版重构所有 Java 类名中的 `Expense` 历史命名。
- 不把支出预算执行逻辑扩展到收入。

## 命名调整

web 端菜单：

- `我的支出` 改为 `我的收支`
- `支出分析` 改为 `收支分析`
- `支出计划` 改为 `预算计划`
- `支出流水` 改为 `收支流水`
- `支出分类` 改为 `收支分类`

iOS/mobile 端：

- 支出主功能入口改为 `收支`
- 流水相关标题改为 `收支流水`
- 分类相关标题改为 `收支分类`
- 预算功能文案使用 `预算计划`

后端 API 可以保留现有 `/api/actual-expenses`、`/api/expense-categories`、`/api/expense-analytics` 路径作为第一版兼容接口，但响应和请求增加收支类型字段。

## 数据模型

### 流水类型

新增枚举值：

- `EXPENSE`：支出
- `INCOME`：收入

### `actual_expenses`

在现有表上新增字段：

- `transaction_type varchar(20) not null default 'EXPENSE'`

约束与索引：

- 金额 `amount` 继续存正数，收入和支出都不存负数。
- 新增索引 `idx_actual_expenses_user_type_date (user_id, transaction_type, expense_date)`。
- 历史数据默认 `EXPENSE`。

### `expense_categories`

在现有表上新增字段：

- `category_type varchar(20) not null default 'EXPENSE'`

约束与索引：

- 同一用户下，分类唯一性从 `(user_id, parent_id, name)` 调整为 `(user_id, category_type, parent_id, name)`。
- 父子分类必须同类型。后端服务在创建/更新时校验：收入小类不能挂到支出大类下，反之亦然。
- 预算计划只能选择 `EXPENSE` 分类。

### 默认收入分类

为每个用户提供初始收入分类。第一版可以用大类即可，仍允许后续新增小类：

- 工资
- 奖金
- 理财收益
- 副业
- 红包转账
- 其他收入

如果系统已有用户，迁移脚本或启动初始化逻辑为用户补齐这些收入分类。不能重复插入同名同类型分类。

## 后端行为

### 流水接口

`ActualExpense`、`ActualExpenseView`、保存请求和列表响应增加字段：

- `transactionType`

列表查询支持过滤：

- `transactionType` 可为空，空表示收入和支出全部返回。
- `categoryId` 仍支持大类或小类过滤，但需要和 `transactionType` 组合使用。
- 如果只传分类不传类型，后端按分类 ID 所属类型自然过滤。

保存校验：

- `transactionType` 必须是 `EXPENSE` 或 `INCOME`。
- `amount` 必须大于 0。
- `categoryId` 必须属于当前用户，且分类类型必须等于 `transactionType`。
- `merchant` 字段继续作为“备注”字段使用，第一版不改数据库列名。

### 分类接口

`ExpenseCategory` 和 DTO 增加：

- `categoryType`

列表接口支持：

- `categoryType` 可为空，空表示返回全部分类。
- web/iOS 端在分类管理与流水表单中按类型过滤展示。

删除校验：

- 收入分类被收入流水使用时不能直接删除。
- 支出分类被支出流水或预算计划使用时不能直接删除。

### 预算计划

`FixedExpenseService`、`FixedExpenseMapper` 和相关接口只使用 `EXPENSE` 分类。

预算执行统计只统计 `transaction_type = 'EXPENSE'` 的流水。收入流水不进入预算执行。

### 收支分析

新增或扩展分析结果，支持月度核心指标：

- `incomeAmount`
- `expenseAmount`
- `balanceAmount`

其中：

- `incomeAmount = sum(amount where transaction_type = 'INCOME')`
- `expenseAmount = sum(amount where transaction_type = 'EXPENSE')`
- `balanceAmount = incomeAmount - expenseAmount`

趋势图：

- 按月收入趋势
- 按月支出趋势
- 按月结余趋势

分类图：

- 收入分类占比，只统计 `INCOME`
- 支出分类占比，只统计 `EXPENSE`

原有预算执行分析保留在“收支分析”的预算执行区域，只显示支出预算与实际支出。

## Web 端设计

### 导航

左侧菜单改为：

- 我的收支
  - 收支分析
  - 预算计划
  - 收支流水
  - 收支分类

内部 view key 可以暂时沿用现有 `expenseAnalysis`、`fixedExpenses`、`actualExpenses`、`expenseCategories`，避免扩大重构。

### 收支流水

筛选区：

- 开始日期
- 结束日期
- 类型：全部 / 收入 / 支出
- 大类
- 小类

当类型选择收入时，分类筛选只显示收入分类；选择支出时只显示支出分类；类型为全部时，分类可以显示全部，但推荐按“收入分类 / 支出分类”分组展示。

指标卡：

- 收入：绿色
- 支出：红色
- 结余：正数绿色，负数红色

表格列：

- 日期
- 类型
- 大类
- 小类
- 金额
- 备注
- 操作

金额展示：

- 收入绿色
- 支出红色
- 金额文本仍显示正数，不加负号

新增/编辑弹框：

- 类型：收入 / 支出，使用分段控件或单选按钮
- 日期
- 大类
- 小类
- 金额，正数
- 备注

切换类型时：

- 清空已选择分类
- 分类下拉切换为对应类型

### 收支分类

顶部增加类型切换：

- 支出分类
- 收入分类

分类管理仍保留大类/小类层级。新增分类时自动带上当前类型。编辑分类不能把已有分类改到另一种类型，避免影响历史流水和预算计划。

### 预算计划

页面标题改为 `预算计划`。分类下拉只显示支出分类。

### 收支分析

页面标题改为 `收支分析`。顶部保留年份、月份、分类层级筛选。

新增核心指标区：

- 本月收入
- 本月支出
- 本月结余

预算执行区域保留现有内容，但标题文案改为“预算执行”，避免和收入统计混淆。

## iOS/mobile 端设计

### 导航与标题

支出相关入口改为“收支”。移动端首屏或收支页显示：

- 本月收入
- 本月支出
- 本月结余

### 流水列表

流水列表展示收入和支出混合时间线：

- 收入金额绿色
- 支出金额红色
- 每条显示类型、分类、备注

### 流水编辑

移动端新增/编辑表单增加类型选择：

- 收入
- 支出

金额仍输入正数。分类选择根据类型过滤。备注字段继续提交到 `merchant`。

### 分类管理

移动端分类管理增加收入/支出切换，分类新增和编辑按当前类型处理。

## 数据迁移

需要新增迁移脚本：

1. 给 `actual_expenses` 添加 `transaction_type`，默认 `EXPENSE`。
2. 给 `expense_categories` 添加 `category_type`，默认 `EXPENSE`。
3. 调整分类唯一索引，加入 `category_type`。
4. 添加流水类型日期索引。
5. 为已有用户插入默认收入分类。

`AuthSchemaInitializer` 也需要保持幂等 DDL，确保本地或远程数据库缺字段时能补齐。

## 测试策略

后端：

- 流水保存收入时写入 `transactionType = INCOME`。
- 流水保存支出时写入 `transactionType = EXPENSE`。
- 收入流水不能选择支出分类。
- 支出预算统计只统计支出流水。
- 月度统计能正确返回收入、支出、结余。
- 分类列表能按收入/支出过滤。

Web：

- 收支流水新增收入后列表显示绿色金额。
- 新增支出后列表显示红色金额。
- 切换类型后分类下拉只显示对应类型。
- 收支分析显示收入、支出、结余。
- 预算计划分类选择不出现收入分类。

iOS/mobile：

- 收支页能显示收入、支出、结余。
- 流水编辑类型切换能刷新分类列表。
- 保存收入/支出都提交正数金额和正确类型。

## 风险与约束

- 现有测试桩已有编译不匹配问题，实施前需要修复或在计划中明确处理。
- 后端命名仍有 `Expense` 历史名，第一版只扩展字段，不做大规模重命名。
- 远程 MySQL 已确认使用 `101.33.233.232:3578`，实施迁移前需要备份或至少确认迁移脚本可重复执行。
- `merchant` 数据库列在第一版继续作为“备注”使用，避免做列名迁移。

## 验收标准

- web 端“我的支出”所有可见入口改成“我的收支”语义。
- web 端可以新增收入流水，并在当月收入统计中体现。
- web 端可以新增支出流水，并在当月支出统计中体现。
- web 端结余 = 收入 - 支出。
- iOS/mobile 端可以新增收入和支出，并显示正确颜色与统计。
- 收入分类不会出现在预算计划中。
- 历史支出数据仍显示为支出，预算执行结果不因收入功能改变。
